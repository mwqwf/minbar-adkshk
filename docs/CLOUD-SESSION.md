## ٢. ⛔ القاعدة التي لا تُنسى في السحابة: لا أسرار عندك

مفاتيح التوقيع وحساب خدمة Play ومفاتيح R2 **ليست في السحابة ولا في المستودعات** —
هي أسرارٌ في GitHub تُكتب ولا تُقرأ. فلا تحاول التوقيع محلياً ولا الرفع إلى Play
بأداة، ولا تطلب من المالك مفتاحاً.

**كلّ بناءٍ ونشرٍ يجري بسير عملٍ واحد:**

```bash
gh workflow run bundle-with-assets.yml -R mwqwf/minbar-adkshk   # التطبيق ⇐ الإنتاج
gh workflow run build-publish.yml -R mwqwf/minbar-adkshk-admin  # اللوحة ⇐ الاختبار المغلق
gh workflow run emulator-check.yml -R mwqwf/minbar-adkshk       # برهان المحاكي
gh workflow run deploy.yml -R mwqwf/minbar-cloud                # الخادم (يحتاج CLOUDFLARE_API_TOKEN)
```

```bash
gh workflow run play-status.yml -R mwqwf/minbar-adkshk            # حالة التطبيقين في Play (قراءة)
gh workflow run deploy.yml -R mwqwf/minbar-cloud -f what=schema   # مخطّطات D1
gh workflow run deploy.yml -R mwqwf/minbar-cloud -f what=query -f sql="SELECT …"   # استعلام قراءة
```

والتحقّق من النتيجة **يُقرأ من السجلّ لا يُفترض**:

```bash
gh run list -R <المستودع> -L 1
gh run view <id> -R <المستودع> --log | grep -aE "jar verified|المعالجات:|ملفّات الصوت:|Uploading|error"
```

## ٣. معنى «ابنِ» و«ارفع» (أمر المالك 2026-09-12)

ثلاثةٌ معاً، لا واحد:
1. **رفع الإصدار**: `versionCode` و`versionName` في `app/build.gradle.kts`، **و«حول»**
   (`ui/AboutScreen.kt`) **وملاحظات الإصدار** (`data/ReleaseNotes.kt`) — القاعدة قديمة وملزمة.
2. **البناء على GitHub** لا على أيّ جهاز.
3. **النشر آلياً**: التطبيق ⇐ **`production` مباشرةً**، واللوحة ⇐ **`alpha` (الاختبار المغلق) دائماً**.
   ⛔ ولا تُرقّى اللوحة إلى الإنتاج إلا بكلمة المالك.

ولأن التطبيق يذهب إلى الإنتاج بلا وسيط بشريّ، **خمسة حرّاس في سير العمل يُسقطون النشر**:
اختبارات الوحدة قبل البناء · `jar verified` ببصمة مفتاح الرفع · أربعة معالجات على الأقلّ ·
لقطة الكتالوج حاضرة · ≥400 ملفّ صوت في حزم الأصول. لا تُضعِف حارساً منها.

## ٤. المعمارية في سطور

- **الخلفية**: `minbar-api` على Cloudflare (Worker + D1 + R2) — لا Firebase البتّة في التطبيق،
  وفي اللوحة `firebase-auth` وحدها انتقالياً حتى ينتقل كلّ المشرفين إلى «جلسة منبر».
- **الصوت**: R2 (`serving/{sha}.ogg`) + مرآة على Vercel. و**حزمتا أصول Play** (`core`/`rest`)
  تحملان المكتبة كلّها فتصل مع التطبيق.
- **الإشعارات**: لا FCM. نبضٌ تكيّفي من `media.menbar.app/pulse.js` (30 د ← 12 س بحسب حداثة الجديد).
- **هوية المشرفين**: «جلسة منبر» (`/admin/session/exchange`) أو رمز ربط (`/access/redeem`).

## ٥. ⛔ محرّمات تكلّف غالياً (كلٌّ منها وقع فعلاً)

1. **لا `ndk { abiFilters }` في حزمة متجر** — حصرُ arm64 أسقط 9,432 جهازاً ورفضه Play.
2. **لا `pull_request_target` ولا `issue_comment`** في أيّ سير عمل — بابا تسريب الأسرار في المستودعات العامّة.
3. **لا حذف لملفّات حزم Play** — البذّار يسجّلها في فهرس التنزيلات؛ حذفُها يُفسد الحزمة صامتاً.
   الحارس `LocalStore.isBundledDownload`، والإزالة الصحيحة `AssetPackSeeder.removeAll`.
4. **لا استعلام عن تطبيقٍ في Play أثناء نشرِه** — كلّ نداء يفتح «تحريراً»، والثاني يُبطل الأوّل
   فيسقط النشر بعد رفع الحزمة كاملة.
5. **لا إيداع لأيّ سرّ** ولا لمفتاح، ولا `git add <مجلّد>` (يكنس ما لم تكتبه) — بل مسارات صريحة.
6. **أسماء متغيّرات التوقيع تختلف**: `MINBAR_SIGNING_*` للتطبيق و`MINBAR_ADMIN_SIGNING_*` للوحة.
7. **الهاتف ممنوع** للاختبار — المحاكي وحده، وهو الآن في CI (`emulator-check.yml`).

## ٥ب. ⛔⛔ ولا تقل «يلزم حاسوب المالك»

كلّ ما يلزم العملَ صار في السحابة: البناء والتوقيع والنشر والمحاكي وقراءة Play وقاعدة D1
ونشر الخادم. فإن عجزتَ عن شيء فالسبب واحدٌ من ثلاثة، **سمِّه بعينه ولا تُحِل على جهازه**:
1. **سرٌّ ناقص** في المستودع (اسمه يظهر في فشل سير العمل) ⇒ أخبر المالك باسم السرّ وحدَه.
2. **صلاحية رمزك** لا تبلغ مستودعاً آخر ⇒ اطلب منه تشغيل جلسةٍ على ذلك المستودع.
3. **حدٌّ من المنصّة** (سقف Play، مراجعة المتجر) ⇒ اذكره بنصّه.
وما عدا ذلك يُنجَز من هنا. ⛔ ولا تطلب منه مفتاحاً ولا كلمة مرور قطّ.
